# Contract-shape conformance check — protocol, fixed before running

18 September 2026. Approved by Christian: "Yes — run the contract-shape conformance check." Paper
only; generation and implementation stay frozen.

## The question it answers

Primary: **is the contract grammar stable enough to begin implementation design?**

Secondary: which proposed amendments or knowledge gaps actually prevent that conclusion.

Completeness of the wider knowledge base is **not** the acceptance criterion [Christian, 18 Sep].

## The boundary, as approved

1. An atomic path register — `register-2026-09-18.json`, with `grammar-sheet-2026-09-18.md`.
2. Restatement of the six existing slice contracts on that register.
3. Hand-derived support across the slice's resolved game.
4. Two blind contracts: Pass Combination Gate and GF4 Transition.

Anything the grammar cannot hold is classified SCHEMA, VOCABULARY or KNOWLEDGE, never repaired during
the exercise. **Any schema amendment that would change a verdict goes back to Christian before
incorporation.** Coach-rule sentences are not audited wholesale; only those the check depends on are
surfaced.

## How it runs

| Stage | What | Independence |
|---|---|---|
| A | Register and grammar sheet written, then reviewed for fidelity to revision 4 and for internal ambiguity | The review does **not** look at slice items, so the register is not tuned to the sample it will be tested on |
| B | Six restatements, one agent per object; the slice game restated on the register by a seventh; two blind contracts | Blind drafters work from the grammar sheet, the register and their object's knowledge only. They do not read the specification, the slice files or this protocol's findings |
| C | Coverage and path matching computed mechanically by script from B's structured output | — |
| D | Support derived by hand, twice, by two independent derivers, on the same restated game and contracts | Neither sees the other |
| E | Every SCHEMA failure adversarially verified; ledger consolidated; the criterion below applied | — |

## The stability criterion (fixed now, before any result)

| Test | Passes when |
|---|---|
| **S1 Holdability** | Every item and non-claim across the eight contracts is placed on a register row with a registered requirement kind, or classed VOCABULARY or KNOWLEDGE. SCHEMA items are listed; S1 holds if every SCHEMA item is LOCAL |
| **S2 Mechanical support** | Every disagreement between the two derivers is traced to a named grammar ambiguity (which then becomes a proposed amendment) or to a verified reader error. Any untraced disagreement fails S2. The agreement rate is reported but is not itself the test |
| **S3 Coverage** | Every contract declares every register row using only the four declaration types |
| **S4 Blind transfer** | The two blind contracts produce no STRUCTURAL SCHEMA failure |

**Verdict:**
- **STABLE:** S1–S4 hold with no SCHEMA failures.
- **STABLE WITH LOCAL AMENDMENTS:** S1–S4 hold, and the only failures are LOCAL SCHEMA amendments. They
  are listed, and those that change a verdict go to Christian first.
- **NOT STABLE:** any STRUCTURAL SCHEMA failure, or S2 fails.

KNOWLEDGE entries never count against stability. VOCABULARY entries are logged for the independent
vocabulary review (SD-18).

**Run conventions RC-1 to RC-36** (`derivation-rules-2026-09-18.md` §9) are reported one by one: was
it needed, and did it change any verdict?

## Stage A outcome, before any contract was restated

Two reviewers checked the register and grammar against revision 4 only. Neither looked at slice items.
- **Needed before the run:** 16 findings.
- **Should fix:** about a dozen more.

Almost all were places where two careful readers would apply the grammar differently, which would have
made S2 unmeasurable. They became run conventions RC-11 to RC-36, and the register was rebuilt (version
2):
- compound rows were split into atomic ones;
- transition qualifiers got their own rows;
- a primary-event existence row was added;
- the fillable list was made exhaustive;
- each citable standing decision was typed as an item.

The grammar sheet was split in two, so the blind drafters receive nothing about derivation or about
particular knowledge objects:
- the contract-writing sheet;
- `derivation-rules-2026-09-18.md`, for restaters and derivers only.

**Revision 4's grammar needed 26 added reading rules before two readers could apply it the same way.
That count is itself part of the answer to the primary question.**

**One clarification of S3**, written now, before any contract is restated:
- A restated slice contract that never examined a row is recorded `UNDECLARED`. That is a gap in the
  older, prose-era contract, classed KNOWLEDGE (authoring coverage). It is not a grammar failure.
- S3 tests whether every row **can** be declared with the four types.
- The two blind contracts, drafted fresh under the grammar, must declare every row in full.
