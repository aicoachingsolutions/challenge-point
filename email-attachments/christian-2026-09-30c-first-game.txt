V17 AND V18 — THE SEMANTIC DISTINCTION

  V17  value.informationRules[].trigger              "trigger (closed list), or STANDING"
  V18  value.informationRules[].dimensions.D006      IE-D006 values

V17 names the GAME EVENT on which information becomes available, from the same
closed list transitions draw on. V18 names the IE CLASSIFICATION of that event —
whether it is a teammate action, an opponent action, an environmental event, an
external signal, and so on — and carries IE-D006's integrity condition, that the
trigger be detectable and causally connected to the information it reveals.

In the Pass Combination case: V18 = TEAMMATE_ACTION says the count changes on
something a teammate does. V17 would say WHICH event — and here is the substance:
the register's trigger list has no member for a completed pass, so V17 cannot
name it. Its current value is STANDING, an assumption your ruling contradicts.

Would withdrawing V17 lose anything? For this object, no: TEAMMATE_ACTION plus
IMMEDIATE_AFTER_TRIGGER already says the count updates on each pass, and no
consequence or gate reads V17 for this rule. But for an information rule whose
trigger IS a represented game event — a score, a turnover, a region entry — V17
carries the identity of that specific event, and V18 only its category. Two
different rules triggered by two different region entries would be
indistinguishable on V18 alone.

So my reading: V17 and V18 are not parallel representations of the same thing —
one names the instance, the other its type. They overlap only where the event has
no represented identity, which is exactly the Pass Combination case. The narrow
option that avoids both a new vocabulary member and a parallel representation is
to let V17 be legitimately absent where the triggering event is not itself a
represented game event, with V18 carrying the classification. I have not
implemented that; it is a ruling about what V17 means when empty.
