3 · A NEW BOUNDED DEFECT, REPORTED NOT REPAIRED — a clause reports the wrong unit, and it defeats the one
    counter that exists to catch it

Found while checking correction 1, and it is a trust defect in gate evidence rather than trigger architecture.

`GA-TRIGGER-UNIQUE`'s first clause is *"transition classes applying to one trigger are mutually compatible"* — its
unit is **pairs**. On the normal path it correctly reports the number of pairs actually compared, so two
transitions with different triggers yield zero and the clause honestly records that it found no applicable
instance. **On the early-return path it reports the number of transitions instead.** With exactly one transition
that is 1, and the basis rule is `instances > 0 ? EVALUATED : NO_APPLICABLE_INSTANCES`.

**So the clause declares `EVALUATED, instances: 1` having compared nothing.** With zero transitions it happens to
be right, because 0 maps to the correct basis. **It is wrong precisely when there is exactly one transition —
which is every one of the eight affected goals.**

The part that makes it worth your attention: the gate report carries a `clausesVacuous` tally that counts clauses
passing on no applicable instance. **That tally exists to surface exactly this, and reporting the wrong unit is
what keeps this clause out of it.** The correct value is a one-argument change, and the same function already does
it correctly fifteen lines later.

Not repaired. It is small and the precedent is in the same file, but it changes gate evidence for eight goals and
you have that surface frozen, so it is yours to release.
